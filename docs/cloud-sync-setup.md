# 云同步部署指南（腾讯云开发 CloudBase）

客户端已经写好了，只差一个后端。这份文档是把后端跑起来的最短路径，大约 20 分钟。

> 客户端只依赖一个 HTTP 接口，所以你不一定非要用 CloudBase。任何能实现 `POST /sync` 的服务都行，协议见本文末尾。

---

## 1. 创建环境

1. 打开 [腾讯云开发控制台](https://console.cloud.tencent.com/tcb)，用微信或 QQ 登录
2. 点「新建环境」，选**按量计费**（个人日程的量级基本落在免费额度内）
3. 环境创建好后，记下**环境 ID**，形如 `daily-list-8gxxxxxx`

## 2. 建两个集合

左侧「数据库」→「集合管理」→ 新建集合：

| 集合名      | 用途           |
| -------- | ------------ |
| `events` | 存放日程记录       |
| `meta`   | 存放每个用户的序号计数器 |

建完后给 `events` 加索引（很重要，否则数据多了会变慢）：

- 「数据库」→ `events` → 「索引管理」→ 新建索引
- 索引字段：`userId` 升序 + `seq` 升序
- 索引名随便填，比如 `user_seq`
- **不要**勾选「唯一」

## 3. 部署云函数

1. 左侧「云函数」→「新建云函数」
2. 函数名填 `sync`
3. 运行环境选 **Node.js 16** 或更高
4. 创建方式选「上传代码包」或「在线编辑」，把 `cloudbase/functions/sync/` 下的两个文件放进去：
   - `index.js`
   - `package.json`（依赖 `@cloudbase/node-sdk`，在线上编辑器里点「安装依赖」）
5. 保存并部署

## 4. 配置 HTTP 访问服务

1. 左侧「云函数」→「HTTP 访问服务」（部分版本叫「云接入」）
2. 新建一条路径：
   - 路径：`/sync`
   - 方法：`POST`
   - 关联函数：`sync`
3. 保存后会得到一个访问地址，形如：

```
https://daily-list-8gxxxxxx.service.tcloudbase.com/sync
```

**把这个地址去掉末尾的 `/sync` 填进应用**（应用会自动拼上 `/sync`）：

```
https://daily-list-8gxxxxxx.service.tcloudbase.com
```

## 5. 生成访问令牌

令牌就是你和服务器之间的约定密码，随便生成一个长随机串，两台设备填同一个。

在任意终端执行：

```bash
openssl rand -hex 32
# 或者用 Node：
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

得到类似 `a3f9c2...` 的 64 位字符串，**复制保存好**——服务端只存它的哈希，丢了没法找回，只能换新的（换新后旧设备需要重新填）。

> 这个令牌等同于你日程数据的钥匙，不要发到群里或提交到 Git。

## 6. 在应用里配置

1. 打开日程 → 设置 → 拉到「云同步」
2. 打开开关
3. 服务地址填第 4 步的地址（不带 `/sync`）
4. 访问令牌填第 5 步生成的字符串
5. 点「保存」，然后点右边的刷新按钮「立即同步」

第一次同步会显示「推送 N 条，拉取 M 条」。

## 7. 在第二台设备上

重复第 6 步，填**同一个**服务地址和**同一个**令牌。同步完成后，两台设备应该看到相同的日程。

## 8. 验证是否真的通了

在一台设备上新建一条日程，等 3 秒左右（应用会自动推送），然后在另一台点「立即同步」，应该能看到。

也可以在云开发控制台的「数据库」→ `events` 里直接看到记录。

## 同步规则（了解这些能避免困惑）

| 场景         | 行为                    |
| ---------- | --------------------- |
| 两台设备改同一条   | 按修改时间取新的，旧的那次被覆盖      |
| 一台删除       | 删除会作为「墓碑」同步过去，另一台也会消失 |
| 两台同时新建     | 各自保留，不会冲突             |
| 订阅的日历（ICS） | **不参与同步**，每台设备各自拉取    |
| 悬浮窗位置、窗口设置 | **不参与同步**，每台设备独立      |

## 自动同步的时机

- 应用启动后 4 秒
- 本地改动后 2.5 秒（连续编辑会合并成一次请求）
- 每 5 分钟轮询一次
- 手动点「立即同步」

## 排查

**「访问令牌无效或已过期」**  
令牌填错了，或者换了新令牌但另一台设备没更新。

**「同步服务返回 404」**  
HTTP 访问服务的路径没配成 `/sync`，或者服务地址多填了 `/sync`（应用会自动拼）。

**「请求超时」**  
检查环境 ID 是否填对、云函数是否部署成功。可以在浏览器里直接访问地址看返回：

```bash
curl -X POST https://你的地址/sync \
  -H "Authorization: Bearer 你的令牌" \
  -H "Content-Type: application/json" \
  -d '{"lastSeq":0,"changes":[]}'
```

正常应返回 `{"serverSeq":0,"records":[]}`。

**数据不同步但没报错**  
检查两台设备的令牌是否完全一致（多一个空格也会被当成不同用户，数据会被隔离在两个空间里）。

## 协议（想换后端时看这里）

客户端只发一个请求：

```http
POST {服务地址}/sync
Authorization: Bearer {令牌}
Content-Type: application/json

{
  "lastSeq": 12,
  "deviceId": "xxxx",
  "changes": [
    { "id": "...", "payload": { ...完整事件对象 }, "updatedAt": 1760000000000, "deleted": false }
  ]
}
```

期望返回：

```json
{
  "serverSeq": 15,
  "records": [
    { "id": "...", "payload": { ... }, "updatedAt": 1760000000000, "deleted": false, "seq": 13 }
  ]
}
```

要求：

- `serverSeq` 单调递增，客户端拿它当增量游标
- 只返回 `seq > lastSeq` 的记录
- 冲突按 `updatedAt` 取新（服务端负责判断）
- 同一条记录重复推送必须幂等

`scripts/mock-sync-server.mjs` 是一份 100 行的参考实现，可以直接跑起来对照。
