# 2026-10-18

## 桌面日程软件（daily-list）从零搭建

用户需求：日程软件，至少要月/周/日视图、能最小化到任务栏、有桌面组件。
澄清后确认：Electron + React、桌面悬浮小窗、本地存储（用户原选「本地+云同步」）。

### 技术选型与关键决策
- **Electron 33 + React 18 + TS + electron-vite**，主进程 CJS 输出（package.json 无 type:module，故 `__dirname` 可用）
- **存储用单文件 JSON + 原子写**（tmp → rename），刻意不用 better-sqlite3：原生模块需 electron-rebuild，会大幅提高「装完就能跑」的门槛。数据模型已按多设备同步预留 `id/rev/updatedAt/deleted` + `schemaVersion`，接云同步时无需迁移
- **云同步在 MVP 阶段没做**：账号体系 + 冲突合并 + 离线队列是独立一期工程，产品评审结论是先用本地 + 预留字段
- 悬浮窗用**独立 BrowserWindow + 独立 HTML 入口**（widget.html），不用单页路由切透明——避免一个崩溃拖垮全局

### 踩过的坑（重要，环境相关）
1. 本机 bash 环境默认 `ELECTRON_RUN_AS_NODE=1`，直接 spawn electron 会退化成纯 Node，报 `Cannot read properties of undefined (reading 'isPackaged')`。**启动测试必须 delete 这个 env**
2. 该环境无可用 GPU，且 Chromium 沙箱会拖垮 GPU 进程 → 必须 `--no-sandbox --disable-gpu --disable-gpu-compositing`，并配合 `app.disableHardwareAcceleration()`（源码里用 `DAILY_LIST_DISABLE_GPU=1` 环境变量守卫）
3. `win.on('minimize')` 在 Electron 类型定义里 listener 是 `() => void`，**不能 preventDefault**，只能直接 `win.hide()`
4. CSS Grid：`.tl-head` 放在 `grid-template-columns: 54px 1fr` 的容器里必须写 `grid-column: 1 / -1`，否则表头被压进 54px 的第一列，整个时间轴布局塌陷（周视图踩过）
5. `.timeline` 加 `overflow: hidden` 会破坏 sticky 表头，改用子元素圆角

### QA 阶段发现并修复的问题（9 项 + 1 项自查）
- 🔴 全天事件参与 `layoutDay()` 分栏 → 渲染成占满整列色块。修法：时间轴过滤 `!e.allDay`
- 🔴 打包配置缺失 → 补 `dist` 脚本 + nsis 配置 + electron-builder
- 🟠 `parse.ts` 的「下周一」在周日说出时算成 8 天后。正确公式：以周一为周首，`toThisMonday = -((dow+6)%7)`，`inWeek = (target+6)%7`
- 🟡 月视图双击 chip 会同时触发新建 → chip 上 `onDoubleClick` stopPropagation
- 🟡 跨天事件次日片段显示原始 23:00 → 新增 `fmtMinuteOfDay(min)` 按裁剪后分钟数格式化
- 🟡 全天行随内容滚走 → `position: sticky; top: var(--tl-head-h)`，表头高度用 CSS 变量统一
- 🟡 月视图空白新建落在 00:00 → 默认 9:00
- 🟡 悬浮窗位置不校验显示器 → `safeWidgetBounds()` 检查 workArea 交集
- 🟡 设置面板 Esc 关不掉 → 补 keydown 监听
- 🟢 自查发现：「今晚8点」的「今」被吃进标题 → 复合词（今晚/明早/明晚）优先于相对日与时段解析，且只说了「下午」没给时刻时默认 14:00
