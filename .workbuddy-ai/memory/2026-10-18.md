# 2026-10-18

## 桌面日程软件（daily-list）从零搭建

用户需求：日程软件，至少要月/周/日视图、能最小化到任务栏、有桌面组件。
澄清后确认：Electron + React、桌面悬浮小窗、本地存储（用户原选「本地+云同步」）。

### 技术选型与关键决策
- **Electron 33 + React 18 + TS + electron-vite**，主进程 CJS 输出（package.json 无 type:module，故 `__dirname` 可用）
- **存储用单文件 JSON + 原子写**（tmp → rename），刻意不用 better-sqlite3：原生模块需 electron-rebuild，会大幅提高「装完就能跑」的门槛。数据模型已按多设备同步预留 `id/rev/updatedAt/deleted` + `schemaVersion`，接云同步时无需迁移
- **云同步在 MVP 阶段没做**：账号体系 + 冲突合并 + 离线队列是独立一期工程，产品评审结论是先用本地 + 预留字段
- 悬浮窗用**独立 BrowserWindow + 独立 HTML 入口**（widget.html），不用单页路由切透明——避免一个崩溃拖垮全局

### 踩过的坑（重要，环境相关）
1. 本机 bash 环境默认 `ELECTRON_RUN_AS_NODE=1`，直接 spawn electron 会退化成纯 Node，报 `Cannot read properties of undefined (reading 'isPackaged')`。**启动测试必须 delete 这个 env**
2. 该环境无可用 GPU，且 Chromium 沙箱会拖垮 GPU 进程 → 必须 `--no-sandbox --disable-gpu --disable-gpu-compositing`，并配合 `app.disableHardwareAcceleration()`（源码里用 `DAILY_LIST_DISABLE_GPU=1` 环境变量守卫）
3. `win.on('minimize')` 在 Electron 类型定义里 listener 是 `() => void`，**不能 preventDefault**，只能直接 `win.hide()`
4. CSS Grid：`.tl-head` 放在 `grid-template-columns: 54px 1fr` 的容器里必须写 `grid-column: 1 / -1`，否则表头被压进 54px 的第一列，整个时间轴布局塌陷（周视图踩过）
5. `.timeline` 加 `overflow: hidden` 会破坏 sticky 表头，改用子元素圆角

## 第二轮需求（同日追加）

用户提出两点：① 悬浮窗不要永久置顶，要和桌面同级、不遮挡其他应用；② 支持通过链接导入其他日历（ICS 订阅）。

### 需求 A：悬浮窗层级
- **关键洞察（最容易被忽略）**：只改 `DEFAULT_SETTINGS.widgetAlwaysOnTop` 默认值对老用户完全无效——用户跑过一次应用后，`true` 已经写进 `daily-list.json`，新默认值不会覆盖已存在的值。**必须做数据迁移**：`SCHEMA_VERSION` 1→2，在 `load()` 里 `if (version < 2) settings.widgetAlwaysOnTop = false`，并 `saveNow()` 落盘
- 移除了 `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })`，它会让窗口压在全屏应用之上，与需求相反
- 非置顶后窗口会被别的应用压住，`showWidget()` 里补 `moveTop()`；首次创建时窗口还没 ready，用 `once('show')` 兜住竞态
- 悬浮窗标题栏加图钉按钮可一键切回置顶
- 迁移后通过 `app:migrated` IPC 通知渲染进程弹 toast 告知用户

### 需求 B：ICS 日历订阅
- **不引第三方 ICS 库**，手写精简解析器 `src/main/ics.ts`：折行合并（续行以空格/tab 开头）、转义还原（`\,` `\;` `\n` `\\`）、TZID 时区换算（两次偏移修正处理 DST）、VALARM 嵌套隔离、EXDATE
- 重复规则用 `rrule` 库展开（`RRule.parseString` + `dtstart`）
- 网络走 **Electron `net.fetch`** 而不是 Node fetch，以复用系统代理设置
- 同步策略：每次**整体替换**该源的事件（不做 diff，避免 id 规则变化残留脏数据）；展开范围「过去 60 天 ~ 未来 365 天」；单源上限 3000 实例；失败时保留旧数据只记 `lastError`
- 只读语义：订阅事件 `readOnly: true`，编辑弹窗变成查看态，提供「忽略此次」（写 `source.hidden` 黑名单，key = `uid:startISO`）和「复制为我的日程」
- 同一 URL 重复添加按 URL 去重，否则会同步出两份重复事件
- 启动后延迟 5s 同步一次，之后每 6 小时（timer 都 `.unref()`）

### 测试
- `scripts/test-subscribe.mjs`：起本地 HTTP 服务提供 `smoke/test.ics`，13 项断言全绿（折行/转义/RRULE/EXDATE/全天/VALARM 隔离/只读/去重）
- 测试脚本自身踩过的坑：断言计数器 `failures += check(...)` 写反（统计成了通过数）；`\n` 期望值忘了写真实换行；固定端口被占用时 `listen` 静默挂起 → 改随机端口 + `once('error', reject)`

### QA 复测发现并修复（5 个 P1 + 5 个 P3）
- **`net.fetch` 对 AbortSignal 的支持不可靠**：设了 15s 超时也照样挂起，订阅面板永久「同步中」。改用 `net.request`（`abort()` 确定能中断），实测 15.0s 精确返回
- 添加订阅失败仍落盘 → 留下永远失败的僵尸源，每 6 小时重试。改为**先同步成功再 push 进 sources**
- `webcal://` 与 `https://` 指向同一日历被当两个源 → 事件重复。比较前先 `normalizeIcsUrl`
- 迁移提示用 `webContents.send` 会 100% 丢失（页面加载完早于监听注册）→ 改为塞进 `data:get` 返回值，渲染进程主动读
- 截断的 ICS（有 BEGIN 无 END）被当空日历 → 清空用户数据。加 `END:VCALENDAR` 校验
- 其余：转义还原顺序（字面 `\\n` 被误还原）、悬浮窗位置夹取、只读态 Ctrl+Enter、truncated 提示、v3 数据降级
